## 二、实验1回顾:基础指令实现

### 2.1 项目背景:自动驾驶小车控制系统

- **基本指令**:
    - `M`: Move - 向当前朝向前进1格
    - `L`: Left - 左转90度
    - `R`: Right - 右转90度
- **状态维护**: Pose {x坐标, y坐标, heading朝向}
- **朝向**: N(北)、E(东)、S(南)、W(西)

### 2.2 测试用例设计回顾

#### 左转指令测试用例 (L)

```cpp

TEST(ExecutorTest, should_return_facing_N_given_command_is_L_and_facing_is_E)
{
    // given - 准备测试环境
    std::unique_ptr<Executor> executor(Executor::NewExecutor({0, 0, 'E'}));
    
    // when - 执行操作
    executor->Execute("L");
    
    // then - 验证结果
    const Pose target({0, 0, 'N'});
    ASSERT_EQ(target, executor->Query());

```

**左转逻辑**: E→N→W→S→E (逆时针)

#### 右转指令测试用例 (R)

**右转逻辑**: E→S→W→N→E (顺时针)

## 三、新功能扩展:加速指令F

### 3.1 需求描述

**F指令**: Fast - 加速状态切换

- 首次接收F: 进入加速状态
- 再次接收F: 退出加速状态(状态切换)

**加速状态下的行为变化**:

- `M`: 前进**2格**(逐格前进,不跳跃)
- `L`: 先前进1格,**然后**左转90度
- `R`: 先前进1格,**然后**右转90度

### 3.2 示例演示

```
初始位置: (0,0) 朝向N
指令序列: M L F M L M

执行过程:
M       → (0,1) N    // 普通前进1格
L       → (0,1) W    // 左转
F       → (0,1) W    // 进入加速状态
M       → (-2,1) W   // 加速前进2格: (-1,1)→(-2,1)
L       → (-3,1) S   // 加速左转: 先前进到(-3,1),再左转到S
M       → (-3,-1) S  // 加速前进2格
```

### 3.3 直接实现的问题

```cpp

                // ... 重复的移动逻辑
            }
            // 再次重复相同的移动逻辑

            // ...
        }
        // L和R指令也需要类似的嵌套判断
    }
}
```

- 圈复杂度进一步增加

## 四、面向对象重构:封装(Encapsulation)

### 4.1 重构思路

**两步走策略**:

1. **方法抽取**: 将M/L/R三个指令的处理逻辑抽取为独立方法
2. **类封装**: 将方法封装到独立的类中

### 4.2 第一步:方法抽取

#### 抽取Move方法

```cpp
// ExecutorImpl.hpp
class ExecutorImpl final : public Executor
{
private:
    void Move(void) noexcept;
    Pose pose;
};

// ExecutorImpl.cpp
void ExecutorImpl::Move() noexcept
{
    if (pose.heading == 'E') ++pose.x;
    else if (pose.heading == 'W') --pose.x;
    else if (pose.heading == 'N') ++pose.y;
    else if (pose.heading == 'S') --pose.y;
}

void ExecutorImpl::Execute(const std::string& commands) noexcept
{
    for (const auto cmd : commands) {
        if (cmd == 'M') {
            Move();  // 调用抽取的方法
        }
        // ...
    }
}
```

**重构原则**:

- ✅ 每次抽取后立即编译、运行、验证
- ✅ 验证通过后立即提交代码: `git add . && git commit -m 'extract Move()'`
- ✅ 小步快跑,持续验证

#### 同理抽取TurnLeft和TurnRight

```cpp
private:
    void Move(void) noexcept;
    void TurnLeft(void) noexcept;
    void TurnRight(void) noexcept;
```

**观察**: 三个方法签名完全一致,只是实现不同 → 为多态做准备

### 4.3 第二步:类封装

#### 封装MoveCommand类

```cpp
// ExecutorImpl.hpp
class ExecutorImpl final : public Executor
{
private:
    class MoveCommand final
    {
    public:
        void DoOperate(ExecutorImpl& executor) const noexcept
        {
            executor.Move();
        }
    };
};

// ExecutorImpl.cpp
#include <memory>

void ExecutorImpl::Execute(const std::string& commands) noexcept
{
    for (const auto cmd : commands) {
        if (cmd == 'M') {
            std::unique_ptr<MoveCommand> cmder = 
                std::make_unique<MoveCommand>();
            cmder->DoOperate(*this);
        }
        // ...
    }
}
```

**关键点**:

- 使用`std::unique_ptr`智能指针管理对象生命周期
- `DoOperate`方法接受`ExecutorImpl&`引用,实现对执行器的操作
- 内部类封装,隐藏实现细节

#### 封装TurnLeftCommand和TurnRightCommand

```cpp
class TurnLeftCommand final
{
public:
    void DoOperate(ExecutorImpl& executor) const noexcept
    {
        executor.TurnLeft();
    }
};

class TurnRightCommand final
{
public:
    void DoOperate(ExecutorImpl& executor) const noexcept
    {
        executor.TurnRight();
    }
};
```

### 4.4 封装的价值

- ✅ **职责分离**: 每个命令类只负责一个操作
- ✅ **复用性提升**: 命令逻辑可以独立测试和复用
- ✅ **圈复杂度降低**: 每个类的逻辑简单清晰
- ⚠️ **仍存在问题**: 代码仍有重复(三个类结构相似)

## 五、面向对象重构:继承与多态(Inheritance & Polymorphism)

### 5.1 问题分析

```cpp
void ExecutorImpl::Execute(const std::string& commands) noexcept
{
    for (const auto cmd : commands) {
        if (cmd == 'M') {
            std::unique_ptr<MoveCommand> cmder = 
                std::make_unique<MoveCommand>();
            cmder->DoOperate(*this);
        } else if (cmd == 'L') {
            std::unique_ptr<TurnLeftCommand> cmder = 
                std::make_unique<TurnLeftCommand>();
            cmder->DoOperate(*this);
        } else if (cmd == 'R') {
            std::unique_ptr<TurnRightCommand> cmder = 
                std::make_unique<TurnRightCommand>();
            cmder->DoOperate(*this);
        }
    }
}
```

**观察**:

- 三个分支的代码结构几乎完全相同
- 唯一区别是创建的对象类型不同
- 可以通过多态消除重复

### 5.2 接口抽象:虚基类ICommand

```cpp
class ExecutorImpl final : public Executor
{
private:
    class ICommand  // 抽象接口
    {
    public:
        virtual ~ICommand() = default;  // 虚析构函数
        virtual void DoOperate(ExecutorImpl& executor) const noexcept = 0;  // 纯虚函数
    };
};
```

**关键概念**:

- **纯虚函数** (`= 0`): 定义接口规范,必须由子类实现
- **虚析构函数**: 确保通过基类指针删除派生类对象时正确析构
- **抽象类**: 不能实例化,只能作为基类

### 5.3 建立继承关系

```cpp
class MoveCommand final : public ICommand
{
public:
    void DoOperate(ExecutorImpl& executor) const noexcept override
    {
        executor.Move();
    }
};

class TurnLeftCommand final : public ICommand
{
public:
    void DoOperate(ExecutorImpl& executor) const noexcept override
    {
        executor.TurnLeft();
    }
};

class TurnRightCommand final : public ICommand
{
public:
    void DoOperate(ExecutorImpl& executor) const noexcept override
    {
        executor.TurnRight();
    }
};
```

**关键字说明**:

- `override`: 明确标记覆盖虚函数,编译器检查
- `final`: 禁止进一步继承,优化性能

### 5.4 利用多态简化代码

```cpp
void ExecutorImpl::Execute(const std::string& commands) noexcept
{
    for (const auto cmd : commands) {
        std::unique_ptr<ICommand> cmder;  // 基类指针
        
        if (cmd == 'M') {
            cmder = std::make_unique<MoveCommand>();
        } else if (cmd == 'L') {
            cmder = std::make_unique<TurnLeftCommand>();
        } else if (cmd == 'R') {
            cmder = std::make_unique<TurnRightCommand>();
        }
        
        if (cmder) {
            cmder->DoOperate(*this);  // 多态调用
        }
    }
}
```

**多态机制**:

- 基类指针`ICommand*`指向派生类对象
- 运行时根据实际对象类型调用对应的`DoOperate`方法
- 消除了代码重复,提升了可扩展性

### 5.5 继承与多态的价值

- ✅ **代码复用**: 相同逻辑只写一次
- ✅ **扩展性强**: 新增命令只需添加新的派生类
- ✅ **维护性高**: 修改某个命令不影响其他命令
- ✅ **符合开闭原则**: 对扩展开放,对修改封闭

**问题**: 编译错误 - 没有为Pose定义`operator==`

**解决方案**: 将运算符重载独立到单独文件

```cpp
// tests/PoseEq.hpp

namespace adas
{
    bool operator==(const Pose& lhs, const Pose& rhs);
}

// tests/PoseEq.cpp
#include "PoseEq.hpp"
#include <tuple>

namespace adas
{
bool operator==(const Pose& lhs, const Pose& rhs)
{
    return std::tie(lhs.x, lhs.y, lhs.heading) ==

}
```

**使用`std::tie`的好处**:

- 简洁优雅,避免逐个成员比较
- 利用标准库的元组比较功能
- 易于维护,添加新成员只需修改一处

## 七、面向对象三大特性总结

### 7.1 封装(Encapsulation)

**定义**: 将数据和操作数据的方法绑定在一起,隐藏内部实现细节

**实践要点**:

- **信息隐藏**: 使用`private`/`protected`访问控制
- **接口设计**: 提供清晰的`public`接口
- **职责单一**: 每个类只负责一个功能

**本项目中的应用**:

```cpp
class MoveCommand final : public ICommand
{
public:
    void DoOperate(ExecutorImpl& executor) const noexcept override;  // 公共接口
private:
    // 内部实现细节隐藏
};
```

**价值**:

- 降低耦合度
- 提高代码复用性
- 便于单元测试

### 7.2 继承(Inheritance)

**定义**: 子类继承父类的属性和方法,实现代码复用和扩展

**继承方式**:

- `public继承`: is-a关系,子类是父类的一种
- `protected继承`: 较少使用
- `private继承`: 实现继承,隐藏父类接口

**本项目中的应用**:

```cpp
class ICommand { };  // 抽象基类

class MoveCommand final : public ICommand { };
class TurnLeftCommand final : public ICommand { };
class TurnRightCommand final : public ICommand { };
class FastCommand final : public ICommand { };
```

**继承层次设计原则**:

- 使用`final`防止过深继承
- 虚基类定义接口规范
- 派生类实现具体逻辑

### 7.3 多态(Polymorphism)

**定义**: 同一接口,不同实现,运行时根据对象类型调用对应方法

**多态实现方式**:

1. **编译时多态**: 函数重载、模板
2. **运行时多态**: 虚函数、继承

**本项目中的应用**:

```cpp
std::unique_ptr<ICommand> cmder;  // 基类指针

// 根据指令创建不同的派生类对象
if (cmd == 'M') {
    cmder = std::make_unique<MoveCommand>();
} else if (cmd == 'L') {
    cmder = std::make_unique<TurnLeftCommand>();
}

cmder->DoOperate(*this);  // 多态调用,运行时绑定
```

**多态的价值**:

- 提高代码灵活性
- 符合开闭原则
- 便于功能扩展

### 7.4 面向对象设计原则(SOLID)

#### S - 单一职责原则(Single Responsibility Principle)

每个类只负责一个功能

```cpp
class MoveCommand { };       // 只负责移动
class TurnLeftCommand { };   // 只负责左转
class FastCommand { };       // 只负责状态切换
```

#### O - 开闭原则(Open-Closed Principle)

对扩展开放,对修改封闭

```cpp
// 新增指令只需添加新类,无需修改现有代码
class NewCommand final : public ICommand
{
    void DoOperate(ExecutorImpl& executor) const noexcept override
    {
        // 新指令实现
    }
};
```

#### L - 里氏替换原则(Liskov Substitution Principle)

子类可以替换父类

```cpp
std::unique_ptr<ICommand> cmder = std::make_unique<MoveCommand>();
// MoveCommand可以完全替换ICommand
```

#### I - 接口隔离原则(Interface Segregation Principle)

接口应该小而精

```cpp
class ICommand
{
    virtual void DoOperate(ExecutorImpl& executor) const noexcept = 0;
    // 只定义必要的接口
};
```

#### D - 依赖倒置原则(Dependency Inversion Principle)

依赖抽象而非具体实现

```cpp
std::unique_ptr<ICommand> cmder;  // 依赖抽象接口ICommand
// 而非具体的MoveCommand、TurnLeftCommand等
```

## 十、代码质量指标

### 10.1 圈复杂度(Cyclomatic Complexity)

**定义**: 衡量代码复杂度的指标,计算程序中线性独立路径的数量

**计算方法**:

```
圈复杂度 = 判断节点数 + 1
```

**示例对比**:

#### 重构前(高圈复杂度)

```cpp
void ExecutorImpl::Execute(const std::string& commands) noexcept
{
    for (const auto cmd : commands) {  // +1
        if (cmd == 'M') {              // +1
            if (isFast) {              // +1
                if (pose.heading == 'E') { ++pose.x; }      // +1
                else if (pose.heading == 'W') { --pose.x; } // +1
                else if (pose.heading == 'N') { ++pose.y; } // +1
                else if (pose.heading == 'S') { --pose.y; } // +1
            }
            if (pose.heading == 'E') { ++pose.x; }      // +1
            else if (pose.heading == 'W') { --pose.x; } // +1
            // ... 更多分支
        } else if (cmd == 'L') {       // +1
            // ... 类似的嵌套
        }
        // 圈复杂度 > 20
    }
}
```

#### 重构后(低圈复杂度)

```cpp
void ExecutorImpl::Execute(const std::string& commands) noexcept
{
    for (const auto cmd : commands) {  // +1
        std::unique_ptr<ICommand> cmder;
        if (cmd == 'M') {              // +1
            cmder = std::make_unique<MoveCommand>();
        } else if (cmd == 'L') {       // +1
            cmder = std::make_unique<TurnLeftCommand>();
        } else if (cmd == 'R') {       // +1
            cmder = std::make_unique<TurnRightCommand>();
        } else if (cmd == 'F') {       // +1
            cmder = std::make_unique<FastCommand>();
        }
        if (cmder) {                   // +1
            cmder->DoOperate(*this);
        }
    }
    // 圈复杂度 = 7
}
```

**圈复杂度标准**:

- **1-10**: 简单程序,风险低
- **11-20**: 复杂度中等,需要关注
- **21-50**: 复杂度高,需要重构
- **>50**: 极高复杂度,难以维护

### 10.2 代码重复率

**DRY原则**: Don't Repeat Yourself - 不要重复自己

**重构前问题**:

- 移动逻辑在M、L、R指令中重复出现

**重构后改进**:

### 10.3 可维护性指数

**影响因素**:

- 代码复杂度
- 代码行数
- 注释率
- 模块化程度

**本项目改进**:

- ✅ 降低圈复杂度: 20+ → 7

## 十一、设计模式应用

### 11.1 命令模式(Command Pattern)

**定义**: 将请求封装成对象,从而可以参数化客户端,对请求排队或记录日志,支持撤销操作

**结构**:

```
┌─────────────┐
│   Client    │
└──────┬──────┘
       │
       ▼
┌─────────────┐       ┌──────────────┐
│  Invoker    │──────>│   Command    │
│  (Executor) │       │  (ICommand)  │
└─────────────┘       └──────┬───────┘
                             │
                  ┌──────────┼──────────┐
                  │          │          │
             ┌────▼────┐ ┌──▼────┐ ┌──▼────┐
             │  Move   │ │ Left  │ │ Right │
             │ Command │ │Command│ │Command│
             └─────────┘ └───────┘ └───────┘
                      │
                      ▼
               ┌─────────────┐
               │  Receiver   │
               │(ExecutorImpl)│
               └─────────────┘
```

**本项目实现**:

```cpp
// Command接口
class ICommand
{
public:
    virtual void DoOperate(ExecutorImpl& executor) const noexcept = 0;
};

// 具体命令
class MoveCommand final : public ICommand
{
public:
    void DoOperate(ExecutorImpl& executor) const noexcept override
    {
        if (executor.IsFast()) {
            executor.Move();
        }
        executor.Move();
    }
};

// Invoker(调用者)
void ExecutorImpl::Execute(const std::string& commands) noexcept
{
    for (const auto cmd : commands) {
        std::unique_ptr<ICommand> cmder;
        // 创建命令对象
        if (cmd == 'M') {
            cmder = std::make_unique<MoveCommand>();
        }
        // 执行命令
        if (cmder) {
            cmder->DoOperate(*this);
        }
    }
}
```

**命令模式的优势**:

- ✅ 解耦发送者和接收者
- ✅ 支持命令队列、日志、撤销
- ✅ 符合开闭原则
- ✅ 便于实现宏命令(组合多个命令)

**可扩展功能**:

1. **命令队列**: 延迟执行命令
2. **命令日志**: 记录执行历史
3. **撤销/重做**: 实现Undo/Redo
4. **宏命令**: 组合多个原子命令

### 11.2 工厂模式(Factory Pattern)

**潜在优化**: 创建命令对象可以使用工厂模式

```cpp
class CommandFactory
{
public:
    static std::unique_ptr<ICommand> Create(char cmd)
    {
        switch (cmd) {
            case 'M': return std::make_unique<MoveCommand>();
            case 'L': return std::make_unique<TurnLeftCommand>();
            case 'R': return std::make_unique<TurnRightCommand>();
            case 'F': return std::make_unique<FastCommand>();
            default: return nullptr;
        }
    }
};

// 简化Execute方法
void ExecutorImpl::Execute(const std::string& commands) noexcept
{
    for (const auto cmd : commands) {
        auto cmder = CommandFactory::Create(cmd);
        if (cmder) {
            cmder->DoOperate(*this);
        }
    }
}
```

### 11.3 状态模式(State Pattern)

**当前实现**: 使用`bool fast`标志管理状态

**状态模式优化**: 当状态复杂时可考虑

```cpp
class IState
{
public:
    virtual void Move(ExecutorImpl& executor) = 0;
    virtual void TurnLeft(ExecutorImpl& executor) = 0;
    virtual void TurnRight(ExecutorImpl& executor) = 0;
};

class NormalState : public IState { /* 普通状态实现 */ };
class FastState : public IState { /* 加速状态实现 */ };

class ExecutorImpl
{
private:
    std::unique_ptr<IState> state;  // 当前状态
};
```

**适用场景**:

- 状态数量多(>3个)
- 状态转换逻辑复杂
- 每个状态下行为差异大

## 十二、高级扩展知识

### 12.1 虚函数表(vtable)机制

**多态实现原理**:

```cpp
class ICommand
{
public:
    virtual void DoOperate(...) = 0;  // 虚函数
};

// 编译器生成虚函数表
ICommand vtable:
+-------------------+
| DoOperate地址     | → 纯虚函数,无实现
+-------------------+

MoveCommand vtable:
+-------------------+
| DoOperate地址     | → MoveCommand::DoOperate
+-------------------+

// 对象内存布局
MoveCommand对象:
+-------------------+
| vptr (虚函数表指针) | → 指向MoveCommand vtable
+-------------------+
| 其他成员变量       |
+-------------------+
```

**多态调用过程**:

```cpp
std::unique_ptr<ICommand> cmder = std::make_unique<MoveCommand>();
cmder->DoOperate(*this);

// 底层实现:
// 1. 通过vptr找到MoveCommand的vtable
// 2. 在vtable中查找DoOperate的地址
// 3. 调用MoveCommand::DoOperate
```

**性能影响**:

- 虚函数调用比普通函数调用慢(间接寻址)
- 每个对象增加一个指针大小的开销(vptr)
- 使用`final`可以帮助编译器去虚化优化

### 12.2 RAII(Resource Acquisition Is Initialization)

**原理**: 利用对象生命周期管理资源

**智能指针是RAII的典型应用**:

```cpp
void ExecutorImpl::Execute(const std::string& commands) noexcept
{
    for (const auto cmd : commands) {
        std::unique_ptr<ICommand> cmder = std::make_unique<MoveCommand>();
        // cmder在作用域结束时自动销毁,释放资源
        cmder->DoOperate(*this);
    } // cmder析构,自动delete对象
}
```

**其他RAII应用**:

```cpp
// 文件管理
std::ifstream file("data.txt");  // 构造时打开文件
// 使用file
// 析构时自动关闭文件

// 锁管理
std::lock_guard<std::mutex> lock(mtx);  // 构造时加锁
// 临界区代码
// 析构时自动解锁
```

### 12.3 移动语义(Move Semantics)

**右值引用**:

```cpp
std::unique_ptr<ICommand> cmder = std::make_unique<MoveCommand>();
// make_unique返回右值,触发移动构造
```

**移动与复制的区别**:

```cpp
// 复制: 深拷贝,资源复制
std::vector<int> v1 = {1, 2, 3};
std::vector<int> v2 = v1;  // 复制构造,分配新内存

// 移动: 资源所有权转移
std::vector<int> v3 = std::move(v1);  // 移动构造,v1变为空
```

**unique_ptr不可复制,只能移动**:

```cpp
std::unique_ptr<ICommand> c1 = std::make_unique<MoveCommand>();
// std::unique_ptr<ICommand> c2 = c1;  // 编译错误,禁止复制
std::unique_ptr<ICommand> c2 = std::move(c1);  // OK,移动所有权
```

### 12.4 模板与泛型编程

**命令模式的模板化**:

```cpp
template<typename Executor>
class ICommand
{
public:
    virtual void DoOperate(Executor& executor) const noexcept = 0;
};

template<typename Executor>
class MoveCommand final : public ICommand<Executor>
{
public:
    void DoOperate(Executor& executor) const noexcept override
    {
        executor.Move();
    }
};
```

**优势**:

- 编译期多态,性能更好
- 类型安全
- 代码复用性强

### 12.5 lambda表达式应用

**可以使用lambda简化命令创建**:

```cpp
std::map<char, std::function<std::unique_ptr<ICommand>()>> commandFactory = {
    {'M', []() { return std::make_unique<MoveCommand>(); }},
    {'L', []() { return std::make_unique<TurnLeftCommand>(); }},
    {'R', []() { return std::make_unique<TurnRightCommand>(); }},
    {'F', []() { return std::make_unique<FastCommand>(); }}
};

void ExecutorImpl::Execute(const std::string& commands) noexcept
{
    for (const auto cmd : commands) {
        if (auto it = commandFactory.find(cmd); it != commandFactory.end()) {
            auto cmder = it->second();
            cmder->DoOperate(*this);
        }
    }
}
```

```cpp
    {
        commandHistory.push_back(commands);
        // 执行命令
    }
    
    std::vector<std::string> GetHistory() const
    {
        return commandHistory;
    }
};
```

## 十六、总结与展望

### 16.1 核心知识点总结

#### 面向对象三大特性

1. **封装**:
    
    - 隐藏实现细节
    - 提供清晰接口
    - 降低耦合度
2. **继承**:
    
    - 代码复用
    - 建立is-a关系
    - 支持多态
3. **多态**:
    
    - 统一接口,不同实现
    - 提高灵活性
    - 符合开闭原则

#### 设计原则(SOLID)

- **S**: 单一职责
- **O**: 开闭原则
- **L**: 里氏替换
- **I**: 接口隔离
- **D**: 依赖倒置

#### 最佳实践

- 使用智能指针管理内存
- 善用const和noexcept
- 利用override和final
- 遵循命名规范
- 编写单元测试
