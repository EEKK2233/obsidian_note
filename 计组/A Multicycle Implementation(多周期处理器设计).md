## 二、单周期处理器的缺陷

### 1. **根本问题：时钟周期过长**

**单周期CPU的时钟周期计算**（以Load指令为准）：

```
时钟周期 = PC's Clock-to-Q 
         + Instruction Memory Access Time
         + Register File Access Time
         + ALU Delay (地址计算)
         + Data Memory Access Time
         + Register File Setup Time
         + Clock Skew
```

### 2. **效率低下的原因**

不同指令实际需求差异巨大：

- **R-type指令**：不需要读内存
- **Store指令**：不需要写寄存器（无Setup时间）
- **分支指令**：不需要访问内存和写寄存器
- **Jump指令**：不需要ALU运算、读内存、读/写寄存器

**问题**：所有指令都按最长指令（Load）的时间执行，造成极大浪费！

## 三、多周期处理器的设计思想

### 1. **核心理念**

```
把指令执行分成多个阶段，每个阶段在一个时钟周期内完成
```

**设计原则**：

- 时钟周期以**最复杂阶段**所需时间为准
- 尽量分成**大致相等**的若干阶段
- 每个阶段最多完成**1次访存** 或 **1次寄存器堆读/写** 或 **1次ALU运算**
- 每步都设置存储元件保存执行结果

### 2. **多周期处理器的优势**

|优势|说明|
|---|---|
|**时钟周期短**|只需满足最复杂阶段的要求|
|**周期数灵活**|Load: 5周期；Jump: 3周期|
|**功能部件复用**|ALU可在不同周期重复使用|
|**存储器复用**|指令/数据存储器合用|

### 3. **典型指令周期数**

- **Load (lw)**：5个周期
- **Store (sw)**：4个周期
- **R-type**：4个周期
- **I-type (ori)**：4个周期
- **Branch (beq)**：3个周期
- **Jump (j)**：3个周期

## 四、多周期数据通路架构

### 1. **关键变化**

与单周期相比的主要不同：

```
✓ 只有一个ALU（单周期有多个加法器和ALU）
✓ 只有一个存储器（指令和数据共用）
✓ 增加了多个临时寄存器：
  - IR（Instruction Register，指令寄存器）
  - A、B（保存读出的操作数）
  - MDR（Memory Data Register，内存数据寄存器）
  - BranchTarget（保存分支目标地址）
✓ 增加了多个多路选择器（MUX）
✓ PC和IR需要写使能控制信号
```

### 2. **新增控制信号**

| 信号名          | 位宽  | 功能                                        |
| ------------ | --- | ----------------------------------------- |
| **PCWr**     | 1   | PC写使能（不是每个周期都写）                           |
| **IRWr**     | 1   | 指令寄存器写使能                                  |
| **IorD**     | 1   | 地址源选择（0=PC, 1=ALU输出）                      |
| **ALUSelA**  | 1   | ALU输入A源（0=PC, 1=寄存器A）                     |
| **ALUSelB**  | 2   | ALU输入B源（00=寄存器B, 01=4, 10=立即数, 11=立即数<<2） |
| **PCWrCond** | 1   | 条件写PC（用于分支）                               |
| **PCSrc**    | 2   | PC源选择                                     |
| **BrWr**     | 1   | 分支目标寄存器写使能                                |

## 五、指令执行过程详解

### **前两个周期（所有指令共同）**

#### **周期1：取指令（Ifetch）**

**操作**：

```
IR ← M[PC]
PC ← PC + 4
```

**数据通路**：

- PC → 存储器地址端
- 存储器读出 → IR
- PC → ALU A口，4 → ALU B口
- ALU执行加法 → PC输入端

**控制信号**：

```
PCWr=1, IRWr=1, MemWr=0
IorD=0（选择PC作为地址）
ALUSelA=0（选择PC）
ALUSelB=01（选择常数4）
ALUOp=addu
PCWrCond=x（无关）
```

**状态标识**：State 0

---

#### **周期2：译码/读寄存器（Rfetch/Decode）**

**操作**：

```
busA ← RegFile[rs]
busB ← RegFile[rt]
Target ← PC + 4 + SignExt(Imm16) × 4
```

**关键点**：

- ⚠️ **PC中已是下条指令地址**，但不影响本指令执行（IRWr=0保证IR不变）
- 同时计算分支目标地址（利用ALU空闲时间）
- 进行指令译码，确定指令类型

**控制信号**：

```
IRWr=0（保持IR内容不变）
PCWr=0（不更新PC）
RegWr=0（不写寄存器）
MemWr=0
ALUSelA=0（选择PC）
ALUSelB=11（选择立即数<<2）
ALUOp=addu
BrWr=1（保存分支目标地址）
ExtOp=1（符号扩展）
```

**状态标识**：State 1

---

### **后续周期（根据指令类型分叉）**

### **1. R-type指令（如add, sub, and, or）**

#### **周期3：执行（RExec）**

```
ALU Output ← busA op busB
```

**控制信号**：

```
ALUSelA=1（选择寄存器A）
ALUSelB=00（选择寄存器B）
ALUOp=Rtype（根据func字段）
RegDst=1（选择rd作为目的寄存器）
RegWr=0（还不写，避免竞争）
MemtoReg=0（选择ALU结果）
```

**状态标识**：State 6

#### **周期4：写回（RFinish）**

```
R[rd] ← ALU Output
```

**控制信号**：

```
RegDst=1（保持rd稳定）
RegWr=1（写入寄存器）
ALUSelA=1, ALUSelB=00
ALUOp=Rtype（保持ALU输出稳定）
MemtoReg=0
```

**⚠️ Race问题解决**：

- 周期3：RegDst=1, RegWr=0（先确定写地址）
- 周期4：RegDst=1, RegWr=1（再写入数据）

**状态标识**：State 7

---

### **2. I-type立即数运算（如ori）**

#### **周期3：执行（OriExec）**

```
ALU Output ← busA or ZeroExt[Imm16]
```

**控制信号**：

```
ALUSelA=1
ALUSelB=10（选择扩展后的立即数）
ALUOp=or
RegDst=0（选择rt作为目的寄存器）
RegWr=0
ExtOp=0（零扩展）
MemtoReg=0
```

**状态标识**：State 4

#### **周期4：写回（OriFinish）**

```
R[rt] ← ALU Output
```

**控制信号**：

```
RegDst=0, RegWr=1
ALUSelA=1, ALUSelB=10
ALUOp=or
ExtOp=0
MemtoReg=0
```

**状态标识**：State 5

---

### **3. Load指令（lw）**

#### **周期3：地址计算（MemAdr）**

```
ALU Output ← busA + SignExt[Imm16]
```

**控制信号**：

```
ALUSelA=1
ALUSelB=10
ALUOp=addu
ExtOp=1（符号扩展）
IorD=1（下个周期用ALU输出作地址）
```

**状态标识**：State 8

#### **周期4：读存储器（MemFetch）**

```
MDR ← M[ALU Output]
```

**控制信号**：

```
IorD=1（使用ALU输出作为地址）
MemWr=0（读操作）
RegDst=0（准备写rt）
RegWr=0（还不写）
MemtoReg=1（选择存储器数据）
ALUSelA=1, ALUSelB=10, ALUOp=addu（保持地址稳定）
```

**状态标识**：State 10

#### **周期5：写回（lwFinish）**

```
R[rt] ← MDR
```

**控制信号**：

```
RegDst=0, RegWr=1
MemtoReg=1
IorD=1, ALUSelA=1, ALUSelB=10, ALUOp=addu
（保持数据通路稳定）
```

**状态标识**：State 11

---

### **4. Store指令（sw）**

#### **周期3：地址计算（MemAdr）**

```
与lw相同
```

**状态标识**：State 8

#### **周期4：写存储器（swFinish）**

```
M[ALU Output] ← busB
```

**控制信号**：

```
IorD=1
MemWr=1（写操作）
RegWr=0（不写寄存器）
ALUSelA=1, ALUSelB=10, ALUOp=addu
（必须保持地址稳定！）
ExtOp=1
```

**状态标识**：State 9

---

### **5. 分支指令（beq）**

#### **周期3：分支判断（BrFinish）**

```
if (busA == busB) then PC ← Target
```

**控制信号**：

```
ALUSelA=1
ALUSelB=00（比较两个寄存器）
ALUOp=subu（减法判断是否相等）
PCWrCond=1（条件写PC）
PCSrc=10（选择分支目标地址）
BrWr=0
```

**PC更新条件**：

```
PC写入 = PCWr + (PCWrCond · Zero)
```

- 如果Zero=1（相等），则PC←Target
- 如果Zero=0（不等），则PC保持不变

**状态标识**：State 2

---

### **6. 跳转指令（j）**

#### **周期3：无条件跳转（JumpFinish）**

```
PC ← PC[31:28] || Instr[25:0] || 00
```

**控制信号**：

```
PCWr=1（无条件写PC）
PCSrc=00（选择跳转地址）
其他为0或无关
```

**状态标识**：State 3

## 七、控制器设计

### **1. 控制方式选择**

**摩尔型状态机（Moore Machine）**：

- 输出仅依赖于**当前状态**
- 与输入（操作码）无关
- 稳定性好，易于设计

### **2. 控制器结构**

```
      ┌──────────────────────────┐
      │     组合逻辑电路         │
      │  ┌──────────────────┐    │
输入──┤  │  下一状态逻辑    │    │
Opcode│  │  NS = f(S, Op)   │    │──▶ 下一状态
      │  └──────────────────┘    │
      │                           │
当前──┤  ┌──────────────────┐    │
状态S │  │  输出逻辑        │    │──▶ 控制信号
      │  │  Out = g(S)      │    │
      │  └──────────────────┘    │
      └──────────────────────────┘
                  │
                  ▼
            ┌──────────┐
            │ 状态寄存器│
      Clk──▶│          │
            └──────────┘
```

### **3. 状态转换表（部分）**

|当前状态|操作码|下一状态|
|---|---|---|
|State 0|x|State 1|
|State 1|000100 (beq)|State 2|
|State 1|000010 (j)|State 3|
|State 1|001101 (ori)|State 4|
|State 1|000000 (R-type)|State 6|
|State 1|100011 (lw)|State 8|
|State 1|101011 (sw)|State 8|
|State 2/3/5/7/9/11|x|State 0|
|State 4|x|State 5|
|State 6|x|State 7|
|State 8|100011 (lw)|State 10|
|State 8|101011 (sw)|State 9|
|State 10|x|State 11|

### **4. PLA实现**

**可编程逻辑阵列（PLA）结构**：

```
输入部分：
- 操作码 Op[5:0]
- 当前状态 S[3:0]

输出部分：
- 下一状态 NS[3:0]
- 控制信号（PCWr, IRWr, MemWr, RegWr, IorD, ALUSelA, ALUSelB, ...）
```

**两部分电路**：

1. **左上角**：下一状态逻辑（NS = f(S, Op)）
2. **右下角**：输出逻辑（控制信号 = g(S)）

## 八、性能分析

### **1. CPI计算**

**平均CPI公式**：

```
CPI = Σ(指令占比i × CPIi)
```

**例题1条件**：

- Load: 22%, 5周期
- Store: 11%, 4周期
- R-type/I-type: 49%, 4周期
- Branch: 16%, 3周期
- Jump: 2%, 3周期

**计算**：

```
CPI = 0.22×5 + 0.11×4 + 0.49×4 + 0.16×3 + 0.02×3
    = 1.10 + 0.44 + 1.96 + 0.48 + 0.06
    = 4.04
```

### **2. 性能比较**

**单周期 vs 多周期**：

**情况1**：单周期时钟 = 多周期时钟 × 3.8

```
单周期执行时间 = 指令数 × 1 × (3.8T)
多周期执行时间 = 指令数 × 4.04 × T
比值 = (4.04T) / (3.8T) = 1.06

结论：单周期快6%
```

**情况2**：单周期时钟 = 多周期时钟 × 5

```
单周期执行时间 = 指令数 × 1 × (5T)
多周期执行时间 = 指令数 × 4.04 × T
比值 = (4.04T) / (5T) = 0.808

结论：多周期快20%
```

### **3. 时钟周期确定**

**多周期处理器的机器周期**：

```
机器周期 = max{存储器访问时间, ALU运算时间, 寄存器读/写时间}
```

**例题条件**：

- 存储器：300ps
- ALU：200ps
- 寄存器堆：100ps

**答案**：机器周期 = 300ps（存储器访问最慢）

## 九、关键知识点总结

### **1. 为什么需要PCWr？**

**单周期**：

- PC每个时钟周期自动更新
- 每条指令只需一个周期

**多周期**：

- 一条指令需要多个周期
- PC不能每个周期都更新
- **必须用PCWr精确控制何时更新PC**

### **2. Race（竞争）问题**

**问题**：寄存器写入时，地址和数据必须在写使能之前稳定

**解决方案**：

```
第一个周期：RegDst=1, RegWr=0（先确定写地址）
第二个周期：RegDst=1, RegWr=1（再写入数据）
```

### **3. ALU复用**

**多周期中ALU的多种用途**：

- **周期1**：计算PC+4
- **周期2**：计算分支目标地址
- **周期3及以后**：执行指令的ALU运算

### **4. 存储器复用**

**单周期**：

- 指令存储器和数据存储器分离

**多周期**：

- 合用一个存储器
- 用IorD信号选择地址源（PC或ALU）
- 不同周期访问不同内容

### **5. 临时寄存器的作用**

|寄存器|作用|
|---|---|
|**IR**|保存当前指令（IRWr=0保证不被覆盖）|
|**A, B**|保存读出的操作数|
|**MDR**|保存从存储器读出的数据|
|**BranchTarget**|保存分支目标地址|

## 十、扩展应用

### **应用1：lui指令实现**

**指令功能**：将立即数送到rt寄存器高16位，低16位补0

**修改方案**：

1. 扩展器支持三种模式：
    - 高位零扩展（ExtOp=01）
    - 高位符号扩展（ExtOp=10）
    - 低位零扩展（ExtOp=11）
2. ExtOp从1位扩展为2位
3. 执行过程同ori，4个周期

**控制信号**：

```
周期3: ALUSelA=1, ALUSelB=10, ALUOp=add, ExtOp=11
周期4: 同上 + RegWr=1
```

## 十二、总结

**多周期处理器设计的核心思想**：

```
用时间换空间 → 提高硬件利用率
分阶段执行 → 缩短时钟周期
状态控制 → 实现灵活的指令执行
```

**设计哲学**：

- 不同指令有不同的执行周期数
- 功能部件可以在同一指令的不同周期中重复使用
- 通过增加少量临时寄存器和控制逻辑，显著提高整体性能

**为流水线铺路**： 多周期处理器是单周期到流水线的过渡，其分阶段执行的思想为流水线设计奠定了基础！
