## 二、流水线冒险分类

### **三种冒险（Hazard）类型**

|冒险类型|现象|解决方案|
|---|---|---|
|**结构冒险**|同一部件被不同指令同时使用|设置多个部件（如IM和DM分开）|
|**数据冒险**|后面指令需要前面指令的结果|转发、阻塞、编译优化|
|**控制冒险**|转移/异常改变执行流程|分支预测、延迟槽|

## 三、数据相关的三种形式

### **1. RAW（Read After Write）- 写后读相关**

**定义**：后面指令读取前面指令写入的数据

```assembly
add $r1, $r2, $r3   # 写r1
sub $r4, $r1, $r3   # 读r1 ← RAW相关
```

**特点**：

- ✅ **真相关**（True Dependency）
- ✅ 基本流水线中**最常发生**
- ✅ 本课程重点讨论的类型

---

### **2. WAW（Write After Write）- 写后写相关**

**定义**：两条指令写入同一个单元

```assembly
add $r1, $r2, $r3   # 写r1
sub $r1, $r4, $r5   # 写r1 ← WAW相关
```

**特点**：

- 输出相关（Output Dependency）
- 基本流水线中**不会发生**
- 乱序执行时会发生

---

### **3. WAR（Write After Read）- 读后写相关**

**定义**：后面指令覆盖前面指令读取的单元

```assembly
add $r4, $r1, $r3   # 读r1
sub $r1, $r2, $r3   # 写r1 ← WAR相关
```

**特点**：

- 反相关（Anti Dependency）
- 基本流水线中**不会发生**
- 乱序执行时会发生

**⚠️ 注意**：5阶段基本流水线只需考虑**RAW冒险**！

## 四、控制冒险（Control Hazard）详解

### **1. 控制冒险的现象**

**问题描述**：

```
Beq指令在第4周期进入流水线
├─ "是否转移"在MEM阶段（第7周期）确定
├─ 目标地址在第7周期才送到PC
└─ 第8周期才取出目标地址处的指令

结果：在Beq后，已有3条指令被错误取出！
```

**流水线时序图**：

```
周期:    4    5    6    7    8    9   10   11
Beq:    IF   ID   EX  MEM   WR
指令1:       IF   ID   EX  MEM   WR  ← 错误
指令2:            IF   ID   EX  MEM ← 错误  
指令3:                 IF   ID   EX ← 错误
目标:                          IF   ID
```

**损失时间片 C = 3**（需要清除3条指令）

---

### **2. 分支延迟（Branch Delay）的概念**

**定义**：

```
分支延迟损失时间片(C) = 从分支指令取指到确定分支方向的周期数 - 1
```

**不同阶段确定分支的延迟**：

|确定阶段|延迟时间片|说明|
|---|---|---|
|**MEM阶段**|C = 3|需要清除IF、ID、EX三个阶段的指令|
|**EX阶段**|C = 2|需要清除IF、ID两个阶段的指令|
|**ID阶段**|C = 1|只需清除IF阶段的指令|

## 五、控制冒险的解决方法

### **方法对比总览**

|方法|优点|缺点|效率|
|---|---|---|---|
|**硬件阻塞**|实现简单|每次分支损失3周期|极低|

|**动态预测**|准确率90%+|硬件复杂|高|
|**延迟槽**|编译器优化|指令重排困难|中高|

## 六、静态分支预测（Static Branch Prediction）

### **1. 基本原理**

**核心思想**：总是按照固定的策略进行预测

**基本策略**：

```
默认策略：总是预测"不发生转移"（Not Taken）
         ↓
     继续执行分支指令后的顺序指令
```

### **2. 启发式规则**

可以添加简单的启发式规则提高准确率：

|场景|预测策略|理由|
|---|---|---|
|**循环顶部的分支**|预测不满足|大多数情况会继续循环|
|**循环底部的分支**|预测满足|大多数情况会跳回循环|
|**向后跳转**|预测满足|通常是循环|
|**向前跳转**|预测不满足|通常是条件判断|

**性能**：准确率可达 **65%-85%**

---

### **3. 缩短分支延迟技术**

#### **方法：将分支判断提前到ID阶段**

**原理**：

```
原来：在MEM阶段判断 → 延迟3周期
改进：在ID阶段判断   → 延迟1周期
```

**具体实现**：

**① 转移地址计算提前**

```
原来在MEM阶段：需要等待ALU计算
现在在ID阶段：  IF/ID寄存器中已有PC和立即数
                直接计算 PC+4+4×SignExt(imm16)
```

**② 条件判断提前**

```
原来在EX阶段：使用ALU进行减法比较
现在在ID阶段：使用简单逻辑电路直接比较Rs和Rt
                ┌─ 按位异或
                ├─ 各位相或
                └─ 判断结果是否为0
```

**效果**：

```
原来：C = 3（损失3个周期）
现在：C = 1（损失1个周期）
节省：2个周期！
```

---

### **4. 带静态分支预测的数据通路**

**新增控制信号**：

```
IF.Flush = Branch AND Zero
```

**作用**：

- 当分支条件满足时，IF.Flush = 1
- 将IF/ID流水段寄存器中的指令字清0
- 转变为NOP指令

**两个关键操作**：

1. **转移目标地址 → PC**
2. **清除IF段中的指令**（将指令字清0）

**⚠️ 注意转发问题**：

```assembly
sub $3, $5, $1    # 计算$3
add $1, $5, $2    # 计算$1
beq $1, $3, 7     # 比较$1和$3
```

**问题**：

- beq在ID阶段需要$1和$3的值
- 如果sub或add的结果还未写回，需要**转发**
- 上上条指令：EXE段结果可转发
- 上条指令：结果来不及，引起**1次阻塞**

## 七、动态分支预测（Dynamic Branch Prediction）

### **1. 核心思想**

```
利用程序执行的历史情况
    ↓
动态预测下一次是否转移
    ↓
根据实际情况调整预测策略
```

### **2. 分支历史记录表（BHT）**

**别名**：

- BHT（Branch History Table）
- BPB（Branch Prediction Buffer）
- BTB（Branch Target Buffer）

**结构**：

```
┌─────────────────────────────────────┐
│  分支指令地址  │  转移目标  │  预测位  │
│   低位索引     │   地址    │         │
├─────────────────────────────────────┤
│     0x...04    │  0x1000   │   1     │
│     0x...08    │  0x2000   │   0     │
│     0x...0C    │  0x3000   │   1     │
│      ...       │    ...    │   ...   │
└─────────────────────────────────────┘
```

**关键特性**：

- ✅ 用分支指令地址的**低位**作索引
- ✅ 在**IF阶段**就可以取到预测位
- ⚠️ 低位相同的分支指令**共享**一个表项

---

### **3. 工作流程**

```
① 查找阶段（IF）
   ├─ 用PC低位在BHT中查找
   ├─ 命中：找到对应表项
   └─ 未命中：第一次执行该分支

② 预测阶段（ID）
   ├─ 根据预测位选择分支方向
   ├─ 预测位=1：选择"转移取"
   └─ 预测位=0：选择"顺序取"

③ 执行阶段（EX）
   └─ 实际执行，确定是否转移

④ 修正阶段
   ├─ 预测正确：保持预测位
   ├─ 预测错误：修改预测位
   └─ 未命中：加入新表项
```

---

### **4. 一位预测（1-bit Predictor）**

#### **状态转换图**

```
        ┌───────────────────────┐
        │      预测不发生        │
        │    (Not Taken)        │
        │        状态0          │
        └───────┬───────────────┘
                │
    发生 ┌──────┼──────┐ 不发生
        │      │      │
        ↓      ↑      ↓
    ┌───────────────────────┐
    │      预测发生          │
    │      (Taken)          │
    │        状态1          │
    └───────────────────────┘
        ↑              ↓
    不发生 └──────┬──────┘ 发生
```

**规则**：

- **预测位=0**：预测不发生，实际发生→预测位改为1
- **预测位=1**：预测发生，实际不发生→预测位改为0
- **预测正确**：预测位保持不变

#### **循环示例**

```c
for (i=0; i<N; i++) {
    // 循环体
}
```

**分析**（假设初始预测位=1）：

```
第1次：预测发生，实际发生 ✓ (正确)
第2次：预测发生，实际发生 ✓ (正确)
...
第N次：预测发生，实际发生 ✓ (正确)
最后：预测发生，实际不发生 ✗ (错误)

总结：N+1次中，只错1次
准确率 = N/(N+1)
```

#### **缺点**

**问题**：连续两次分支情况不同时，预测必错

```
例如：T → N → T
第1次：状态1，预测T，实际T ✓
第2次：状态1，预测T，实际N ✗ → 状态改为0
第3次：状态0，预测N，实际T ✗ → 状态改为1
```

---

### **5. 两位预测（2-bit Predictor）**

#### **核心改进**

```
只有连续两次预测错误才改变预测方向
```

#### **四状态转换图**

```
    强不发生(00) ←→ 弱不发生(01)
         ↓               ↓
         ↑               ↑
    弱发生(10)   ←→   强发生(11)
```

**详细状态转换**：

```
        预测不发生              预测不发生
    ┌──────────────┐      ┌──────────────┐
    │   强不发生    │  发生 │   弱不发生    │
    │   状态00     │ ───→ │   状态01     │
    └──────┬───────┘      └──────┬───────┘
     不发生│  ↑                  │  ↑ 不发生
           │  │发生          发生│  │
           ↓  │                  ↓  │
    ┌──────────────┐      ┌──────────────┐
    │   弱发生     │  不发生│   强发生     │
    │   状态10     │ ←─── │   状态11     │
    └──────────────┘      └──────────────┘
        预测发生              预测发生
```

**状态含义**：

|状态|编码|含义|预测|
|---|---|---|---|
|**强发生**|11|最近连续发生|Taken|
|**弱发生**|10|最近一次不发生，之前发生|Taken|
|**弱不发生**|01|最近一次发生，之前不发生|Not Taken|
|**强不发生**|00|最近连续不发生|Not Taken|

#### **转换规则**

```
11 (强发生)
├─ 实际发生   → 保持11
└─ 实际不发生 → 变为10 (弱发生，仍预测发生)

10 (弱发生)
├─ 实际发生   → 变为11 (强发生)
└─ 实际不发生 → 变为01 (弱不发生)

01 (弱不发生)
├─ 实际发生   → 变为10 (弱发生)
└─ 实际不发生 → 变为00 (强不发生)

00 (强不发生)
├─ 实际发生   → 变为01 (弱不发生，仍预测不发生)
└─ 实际不发生 → 保持00
```

### **6. 循环预测对比**

#### **例6.2：单重循环**

```c
for (i=0; i<N; i++) {
    // 循环体
}
```

**一位预测分析**（初始=0）：

```
进入循环时预测错误 → 1次错
循环结束时预测错误 → 1次错
总错误：2次
准确率：(N-1)/(N+1)
```

**两位预测分析**（初始=00）：

```
进入循环：00→预测N，实际T → 错，改为01
第2次：01→预测N，实际T → 错，改为10
第3-N次：10/11→预测T，实际T → 对
最后：11→预测T，实际N → 错
总错误：3次（但前2次可忽略）
准确率：(N-2)/(N+1) ≈ N/(N+1)
```

---

#### **例6.3：双重循环**

```c
for (i=0; i<N; i++) {          // 外循环
    for (j=0; j<N; j++) {      // 内循环
        sum = sum + 1;
    }
}
```

**统计**：

- 外循环分支：执行 **N+1** 次
- 内循环分支：执行 **N×(N+1)** 次

**一位预测**（初始=0）：

```
外循环：最后1次错
内循环：第1次进入错 + 每次退出错
      = 1 + N次 = N+1次错？

实际分析：
- 第一次进入内循环：预测错1次
- 退出内循环改为1，再进入又预测错
- 每次循环有2次错
总错误：1 + 2×(N-1) = 2N-1次

准确率：
外循环：N/(N+1) = 90.9% (N=10)
内循环：约82.7% (N=10)
```

**两位预测**（初始=00）：

```
内循环分析：
第1次进入：00→预测N，实际T → 01
第2次：01→预测N，实际T → 10
第3-N次：10/11→预测T，实际T → 对
退出：11→预测T，实际N → 10
再进入：10→预测T，实际T → 对

每次内循环只有最后1次错！
总错误：N次

准确率：
外循环：90.9% (N=10)
内循环：90.9% (N=10) ← 显著提升！
```

## 八、延迟槽（Delayed Branch）

### **基本思想**

```
把分支指令前面与分支指令无关的指令
调到分支指令后执行
```

### **示例**

**优化前**：

```assembly
    add $1, $2, $3
    sub $4, $5, $6
    beq $1, $4, target
    lw  $7, 0($8)      ← 预测错误时被清除
    ...
target:
```

**优化后**：

```assembly
    add $1, $2, $3
    beq $1, $4, target
    sub $4, $5, $6     ← 延迟槽：无论是否转移都执行
    lw  $7, 0($8)
    ...
target:
```

### **注意事项**

- ✅ MIPS支持**1条延迟槽**
- ❌ RISC-V**不支持延迟槽**
- ⚠️ 延迟槽中的指令必须与分支指令**无数据相关**
- ⚠️ 编译器需要找到合适的指令填充延迟槽

## 九、三种处理器实现方式比较

### **性能分析例题**

**已知条件**：

```
存储器：200ps
ALU：100ps
寄存器堆：50ps

指令比例：
- Load：25%
- Store：10%
- ALU：52%
- Branch：11%
- Jump：2%
```

---

### **1. 单周期处理器**

**时钟周期**：

```
由最长指令（Load）决定：
取指(200) + 读寄存器(50) + ALU(100) + 读存储器(200) + 写寄存器(50)
= 600ps
```

**性能**：

```
执行时间 = N × 1 × 600ps = 600N (ps)
```

---

### **2. 多周期处理器**

**时钟周期**：

```
由最长操作（存储器访问）决定：200ps
```

**各指令周期数**：

- Load: 5周期
- Store: 4周期
- ALU: 4周期
- Branch: 3周期
- Jump: 3周期

**平均CPI**：

```
CPI = 0.25×5 + 0.10×4 + 0.52×4 + 0.11×3 + 0.02×3
    = 1.25 + 0.40 + 2.08 + 0.33 + 0.06
    = 4.12
```

**性能**：

```
执行时间 = N × 4.12 × 200ps = 824N (ps)
```

---

### **3. 流水线处理器**

**时钟周期**：200ps

**各指令平均周期数**（假设）：

```
Load：1.5周期（50%概率load-use冒险）
Store：1周期
ALU：1周期
Branch：1.25周期（75%准确率，延迟=1）
       = 0.75×1 + 0.25×2
Jump：2周期（ID阶段确定）
```

**平均CPI**：

```
CPI = 0.25×1.5 + 0.10×1 + 0.52×1 + 0.11×1.25 + 0.02×2
    = 0.375 + 0.10 + 0.52 + 0.1375 + 0.04
    = 1.17
```

**性能**：

```
执行时间 = N × 1.17 × 200ps = 234N (ps)
```

---

### **性能对比总结**

|实现方式|时钟周期|CPI|执行时间|相对速度|
|---|---|---|---|---|
|**单周期**|600ps|1.0|600N|基准|
|**多周期**|200ps|4.12|824N|0.73×|
|**流水线**|200ps|1.17|234N|**2.56×**|

**结论**：

- 流水线比单周期快 **2.56倍**
- 流水线比多周期快 **3.52倍**

## 十、重要习题解析

### **习题类型总结**

#### **类型1：数据相关识别**

**技巧**：

1. 检查写后读（RAW）相关
2. 画流水线时序图
3. 标注哪个周期读，哪个周期写

#### **类型2：NOP插入计算**

**不转发情况**：

```
需要等待WB完成
→ 插入2条NOP（假设同周期前半写后半读）
→ 插入3条NOP（假设不考虑同周期优化）
```

**转发情况**：

```
ALU结果：可以转发，不需NOP
Load-use：需要1条NOP
```

### **习题6.4：数据相关与转发**

```assembly
1  add $t1, $s1, $s0
2  sub $t2, $s0, $s3
3  add $t1, $t1, $t2
```

**（1）数据相关**：

- 第1条和第3条：关于$t1
- 第2条和第3条：关于$t2

**（2）不转发需要插入的NOP**：

```
需要在第3条前插入2条NOP
（假设同周期前半写后半读）
```

**（3）转发可以完全解决**：

```
第1条的$t1从MEM段转发到第3条的EX段
第2条的$t2从EX段转发到第3条的EX段
```

---

### **习题6.5：Load-use冒险**

```assembly
1  add $s3, $s1, $s0
2  sub $t2, $s0, $s3
3  lw  $t1, 0($t2)
4  add $t1, $t1, $t2
```

**（1）数据相关**：

- 1和2：$s3
- 2和3：$t2
- 2和4：$t2
- 3和4：$t1 ← **Load-use!**

**（3）转发情况**：

```
需要在第4条前插入1条NOP
（第3条是lw，结果在MEM段才产生，无法转发到第4条的EX段）
```

**（4）CPI计算**：

```
不转发：14周期，CPI = 14/4 = 3.5
转发：  9周期，CPI = 9/4 = 2.25
```

### **习题6.7：循环代码优化**

```assembly
loop:
    add $t1, $s3, $s3    # 1
    add $t1, $t1, $t1    # 2
    add $t1, $t1, $s6    # 3
    lw  $t0, 0($t1)      # 4
    bne $t0, $s5, exit   # 5
    add $s3, $s3, $s4    # 6
    j loop               # 7
exit:
```

**数据相关**：

- 1→2→3→4：$t1链
- 4→5：$t0（load-use）
- 6→1：$s3

**控制相关**：

- 第5条：bne
- 第7条：j

**优化分析**：

```
不转发：需要大量NOP
转发：只需1条NOP（在第5条前，解决load-use）
```

## 十三、深入理解动态分支预测

### **1. BHT（分支历史记录表）的详细实现**

#### **表项结构**

```
┌──────────────────────────────────────────────┐
│  索引  │  标签  │  目标地址  │  预测位  │  有效位 │
├──────────────────────────────────────────────┤
│  [n:0] │ [m:n+1]│  32-bit   │  1/2-bit │  1-bit │
└──────────────────────────────────────────────┘
```

**字段说明**：

|字段|位宽|作用|
|---|---|---|
|**索引**|n+1位|PC低位，用于快速查找|
|**标签**|m-n位|PC高位，用于确认命中|
|**目标地址**|32位|转移目标的完整地址|
|**预测位**|1-2位|预测状态|
|**有效位**|1位|表项是否有效|

#### **BHT大小设计**

**典型配置**：

```
BHT大小 = 2^n 个表项

例如：
- n=10 → 1024个表项
- n=12 → 4096个表项
- n=14 → 16384个表项
```

**面积计算**：

```
以1024表项、2位预测为例：
索引：不占表项空间（用于寻址）
标签：假设16位
目标地址：32位
预测位：2位
有效位：1位

每个表项：16 + 32 + 2 + 1 = 51位
总大小：1024 × 51 = 52,224位 = 6.4KB
```

---

### **2. BHT的查找流程详解**

#### **IF阶段：并行查找**

```
时钟周期 t：
    PC[31:0]
        │
        ├─→ 指令存储器（取指令）
        │
        └─→ BHT查找
            │
            ├─ PC[n:0] → 索引
            └─ PC[31:n+1] → 标签
```

**查找步骤**：

```
Step 1: 用PC[n:0]索引到表项
        │
        ▼
Step 2: 比较PC[31:n+1]与表项的标签
        │
        ├─ 相等且有效位=1 → 命中
        └─ 不相等或无效 → 未命中
        │
        ▼
Step 3: 读取预测位和目标地址
```

**时序关键点**：

```
BHT查找必须在IF阶段完成！
→ 需要非常快速的查找
→ 通常使用SRAM实现
→ 单周期访问
```

---

#### **ID阶段：预测决策**

```
时钟周期 t+1：
    ┌─────────────────┐
    │  从IF/ID获取：   │
    │  - 预测位       │
    │  - 目标地址     │
    │  - 指令操作码   │
    └────────┬────────┘
             │
        确认是分支指令？
             │
         ┌───┴───┐
        是          否
         │          │
    根据预测位选择   正常顺序执行
         │
    ┌────┴────┐
   预测位=1   预测位=0
    │          │
  选择目标   选择PC+4
```

---

#### **EX阶段：实际执行**

```
时钟周期 t+2：
    ┌────────────────┐
    │  实际计算：     │
    │  - 比较操作数   │
    │  - 计算目标地址 │
    └────────┬───────┘
             │
      确定实际转移方向
             │
        ┌────┴────┐
      实际转移   实际不转移
```

---

#### **MEM阶段：预测验证**

```
时钟周期 t+3：
    实际方向 vs 预测方向
         │
    ┌────┴────┐
   预测正确   预测错误
    │          │
  继续执行   ┌────────────┐
            │ 1. 冲刷流水线│
            │ 2. 更新PC    │
            │ 3. 修正预测位│
            └────────────┘
```

---

### **3. 预测错误的处理机制**

#### **冲刷（Flush）流水线**

**需要清除的指令**：

```
假设在MEM阶段发现预测错误：
┌──────────────────────────────┐
│ IF阶段：指令1（错误取出）     │ ← 需要清除
│ ID阶段：指令2（错误取出）     │ ← 需要清除
│ EX阶段：指令3（错误取出）     │ ← 需要清除
│ MEM阶段：分支指令（发现错误） │
└──────────────────────────────┘
```

**清除方法**：

```
方法1：将流水段寄存器中的指令字清0
方法2：将流水段寄存器中的控制信号清0
```

**控制信号**：

```
IF.Flush = Branch AND (预测错误信号)

预测错误信号 = (预测方向 XOR 实际方向)
```

---

#### **更新预测表**

**一位预测更新逻辑**：

```verilog
if (actual_taken) {
    prediction_bit = 1;  // 下次预测转移
} else {
    prediction_bit = 0;  // 下次预测不转移
}
```

**两位预测更新逻辑**：

```verilog
case (prediction_state)
    2'b11: // 强发生
        prediction_state = actual_taken ? 2'b11 : 2'b10;
    2'b10: // 弱发生
        prediction_state = actual_taken ? 2'b11 : 2'b01;
    2'b01: // 弱不发生
        prediction_state = actual_taken ? 2'b10 : 2'b00;
    2'b00: // 强不发生
        prediction_state = actual_taken ? 2'b01 : 2'b00;
endcase
```

---

### **4. 分支目标缓冲（BTB）优化**

#### **问题：BHT的局限性**

```
问题：BHT只存预测位，不存目标地址
→ 即使预测转移，仍需等到ID/EX阶段计算目标地址
→ 仍有1-2周期的延迟
```

#### **BTB的改进**

```
BTB = BHT + 目标地址缓存

┌────────────────────────────────┐
│  PC索引  │  预测位  │  目标地址  │
├────────────────────────────────┤
│  [n:0]  │  2-bit  │  32-bit   │
└────────────────────────────────┘
```

**优势**：

```
IF阶段：
├─ 查找BTB
├─ 如果命中且预测转移
└─ 直接使用缓存的目标地址

结果：零周期分支！（预测正确时）
```

**时序对比**：

|技术|预测正确延迟|预测错误代价|
|---|---|---|
|**简单BHT**|1-2周期|2-3周期|
|**BTB**|0周期|2-3周期|

## 十四、高级分支预测技术

### **1. 两级自适应预测器**

#### **基本思想**

```
使用两级历史信息：
第一级：全局历史寄存器（GHR）
第二级：模式历史表（PHT）
```

#### **结构**

```
         分支指令PC
              │
              ▼
      ┌───────────────┐
      │  BHT（第一级） │
      │  存储局部历史  │
      └───────┬───────┘
              │
              ▼
       全局历史寄存器GHR
       (记录最近n个分支结果)
              │
              ├──→ PC异或GHR
              │
              ▼
      ┌───────────────┐
      │  PHT（第二级） │
      │  存储预测位    │
      └───────────────┘
```

**示例：4位GHR**

```
GHR = [b3, b2, b1, b0]
其中bi = 1表示第i个分支发生转移

索引 = PC[n:0] XOR GHR[3:0]
```

---

### **2. 相关预测器（Correlating Predictor）**

#### **(m, n)预测器**

**定义**：

- **m**：使用最近m个分支的结果
- **n**：每个模式使用n位预测位

**示例：(2, 2)预测器**

```
GHR = 2位 → 4种模式
每种模式 → 2位预测

总共：4 × 2 = 8位预测存储
```

**适用场景**：

```c
// 分支相关的例子
if (a > 0) {        // 分支1
    if (b > 0) {    // 分支2
        // ...
    }
}

如果分支1发生，分支2发生的概率很高
→ 可以利用分支1的历史预测分支2
```

---

### **3. 混合预测器（Hybrid Predictor）**

#### **思想**

```
同时使用多种预测器
动态选择最准确的那个
```

#### **Alpha 21264的混合预测器**

```
        分支指令PC
             │
      ┌──────┼──────┐
      │      │      │
      ▼      ▼      ▼
   全局   局部   选择器
   预测器  预测器  
      │      │      │
      └──────┼──────┘
             │
             ▼
        最终预测结果
```

**工作流程**：

```
1. 三个预测器同时预测
2. 选择器根据历史记录选择最准确的
3. 选择器本身也会动态更新
```

---

### **4. 神经网络预测器**

#### **感知器预测器（Perceptron Predictor）**

```
输入：
├─ 当前PC的某些位
├─ 全局历史寄存器
└─ 局部历史

权重：
├─ 每个输入对应一个权重
└─ 根据预测结果动态调整

输出：
└─ 加权和 > 阈值 → 预测转移
```

**优势**：

- 可以捕捉复杂的分支模式
- 准确率可达95%+
- 现代高性能处理器普遍采用

### **2. 代码重组优化**

#### **循环展开（Loop Unrolling）**

**优化前**：

```c
for (i = 0; i < n; i++) {
    a[i] = b[i] + c[i];
}
// 每次迭代1个分支
```

**优化后**：

```c
for (i = 0; i < n; i += 4) {
    a[i]   = b[i]   + c[i];
    a[i+1] = b[i+1] + c[i+1];
    a[i+2] = b[i+2] + c[i+2];
    a[i+3] = b[i+3] + c[i+3];
}
// 每4次迭代1个分支
```

**效果**：

```
分支数量减少 75%
分支预测准确率提高
总体性能提升 10-20%
```

#### **分支消除（Branch Elimination）**

**条件移动指令（CMOV）**：

**优化前**：

```assembly
    cmp  $1, $2
    beq  label
    mov  $3, $4
    j    done
label:
    mov  $5, $4
done:
```

**优化后**：

```assembly
    cmp   $1, $2
    cmov  $3, $5, $4  # 条件移动，无分支
```

**适用场景**：

- 分支预测困难的短代码段
- 两个分支执行时间相近
- 消除分支比预测错误代价更小

---

### **3. Switch语句优化**

#### **跳转表 vs 分支链**

**小范围Switch（查找表）**：

```c
switch (x) {
    case 0: return 10;
    case 1: return 20;
    case 2: return 30;
    case 3: return 40;
}
```

**编译为**：

```assembly
    lw  $t0, table($x)  # 一次访存，无分支
    jr  $t0
```

**大范围Switch（二分查找）**：

```c
switch (x) {
    case 1:   ...
    case 100: ...
    case 500: ...
    // 稀疏的case
}
```

**编译为平衡的分支树**：

```
减少平均分支数
从O(n)降到O(log n)
```

## 二十一、综合练习题

### **练习1：预测准确率计算**

**题目**：某程序包含以下循环

```c
for (i = 0; i < 100; i++) {
    for (j = 0; j < 10; j++) {
        sum += array[i][j];
    }
}
```

计算：

1. 使用一位预测器（初始=1）的准确率
2. 使用两位预测器（初始=11）的准确率

**答案**：

```
外循环：执行101次分支
一位：错1次（最后），准确率100/101=99%
两位：错1次（最后），准确率100/101=99%

内循环：执行100×11=1100次分支
一位：第一次错+每次退出错=1+100=101次错
     准确率=(1100-101)/1100=90.8%
两位：每次只有退出时错=100次错
     准确率=(1100-100)/1100=90.9%
```

3. 如果使用BTB，预测正确时有延迟吗？

**答案**：

### **练习3：性能对比**

**题目**：比较以下三种配置的性能

**条件**：

```
程序统计：
- 分支指令占比：20%
- 非分支指令CPI：1.0
- 时钟周期：1ns

配置A：不使用分支预测（总是阻塞）
配置B：静态预测（准确率80%）
配置C：动态预测（准确率95%）

分支延迟：
- 在EX阶段确定，延迟C=2周期
```

**解答**：

**配置A（不预测）**：

```
每个分支都阻塞2周期
分支CPI = 1 + 2 = 3

总体CPI = 0.8×1 + 0.2×3 = 0.8 + 0.6 = 1.4
执行时间 = N × 1.4 × 1ns = 1.4N ns
```

**配置B（静态预测）**：

```
分支CPI = 0.8×1 + 0.2×(1+2) = 0.8 + 0.6 = 1.4

总体CPI = 0.8×1 + 0.2×1.4 = 0.8 + 0.28 = 1.08
执行时间 = N × 1.08 × 1ns = 1.08N ns
```

**配置C（动态预测）**：

```
分支CPI = 0.95×1 + 0.05×(1+2) = 0.95 + 0.15 = 1.1

总体CPI = 0.8×1 + 0.2×1.1 = 0.8 + 0.22 = 1.02
执行时间 = N × 1.02 × 1ns = 1.02N ns
```

**性能对比**：

```
配置B vs A：1.4/1.08 = 1.30倍加速
配置C vs A：1.4/1.02 = 1.37倍加速
配置C vs B：1.08/1.02 = 1.06倍加速
```

## 二十三、特殊分支场景处理

### **1. 间接分支（Indirect Branch）**

#### **问题描述**

```c
// C语言间接跳转
void (*func_ptr)() = get_function();
func_ptr();  // 目标地址运行时确定

// 汇编
jr $ra  // 目标在寄存器中
```

**挑战**：

- 目标地址不固定
- 普通BTB效果差
- 需要特殊处理

---

#### **间接分支目标缓存（iBTB）**

```
┌────────────────────────────────────┐
│  源地址  │  历史模式  │  目标地址   │
├────────────────────────────────────┤
│  0x1000  │  Pattern1  │  0x2000    │
│  0x1000  │  Pattern2  │  0x3000    │  ← 同一源，不同目标
│  0x1000  │  Pattern3  │  0x4000    │
└────────────────────────────────────┘
```

**关键**：使用调用历史作为索引

```
索引 = hash(PC, 最近几次调用地址)

例如：
func_ptr在main中调用 → 目标A
func_ptr在loop中调用 → 目标B
→ 可以区分！
```

---

#### **Two-Target预测器**

```
观察：大多数间接分支只有1-2个目标

策略：
if (目标数 <= 2) {
    使用简单预测器（2个槽位）
} else {
    使用完整iBTB
}

效果：
覆盖90%的间接分支
硬件开销小
```

### **2. Switch语句优化**

#### **稠密Switch（跳转表）**

```c
switch (x) {
    case 0: return 10;
    case 1: return 20;
    case 2: return 30;
    case 3: return 40;
}
```

**编译后**：

```assembly
    sll  $t0, x, 2      # 计算偏移
    lw   $t1, table($t0) # 查表
    jr   $t1            # 间接跳转
    
table:
    .word target0
    .word target1
    .word target2
    .word target3
```

**分支预测策略**：

```
使用iBTB预测jr指令
通常准确率很高（>95%）
因为跳转模式相对固定
```

---

#### **稀疏Switch（二叉查找）**

```c
switch (x) {
    case 1:   ...
    case 100: ...
    case 500: ...
    case 999: ...
}
```

**编译为平衡树**：

```assembly
    # 第一层：x < 500?
    blt  $x, 500, left
right:
    # 第二层：x < 999?
    blt  $x, 999, case_500
    j    case_999
left:
    # 第二层：x < 100?
    blt  $x, 100, case_1
    j    case_100
```

**优化效果**：

```
分支深度：O(log n)
预测友好：每个分支独立
准确率通常较高
```

### **3. 虚函数调用**

#### **问题分析**

```cpp
class Base {
    virtual void func() = 0;
};

class Derived1 : public Base {
    void func() override { /* ... */ }
};

class Derived2 : public Base {
    void func() override { /* ... */ }
};

Base* obj = get_object();

```

**汇编实现**：

```assembly
lw   $t0, 0($obj)     # 加载vtable指针
lw   $t1, offset($t0) # 加载函数指针
jalr $t1              # 调用函数
```

#### **虚函数预测技术**

**内联缓存（Inline Cache）**：

```
每个调用点记录：
- 最常见的类型
- 对应的目标地址

快速路径：
if (对象类型 == 缓存类型) {
    直接调用缓存的目标
} else {
    正常查找vtable
}
```

**多态内联缓存**：

```
记录前N个（通常2-4个）最常见的类型
覆盖大部分情况
准确率可达90%+
```

**JIT编译器的优化**：

```
运行时统计类型分布
生成特化的代码
→ 消除虚函数开销
```

## 二十四、分支预测与安全

### **1. Spectre攻击原理**

#### **预测执行的副作用**

```c
// 受害者代码
if (x < array_size) {          // 分支1
    y = array[x];
    z = array2[y * 256];       // 缓存加载
}
```

**攻击流程**：

```
1. 训练分支预测器
   → 多次以合法x调用
   → 分支1总是预测为taken

2. 发起攻击
   → 使用非法的x值
   → 分支预测器仍预测taken
   → 预测执行访问array[x]
   → 预测执行访问array2[y*256]

3. 检测结果
   → 虽然预测失败会回滚
   → 但缓存状态已改变
   → 通过侧信道攻击读取y的值
```

---

#### **Spectre变种**

**Variant 1：边界检查绕过**

```c
if (x < size) {
    // 预测执行可能越界访问
    y = data[x];
}
```

**Variant 2：间接分支投毒**

```c
// 训练BTB指向攻击者的代码
indirect_call(target);
```

**Variant 3：Meltdown**

```c
// 跨权限级别的预测执行
// (Intel特有，ARM和AMD不受影响)
```

---

### **2. 缓解措施**

#### **硬件层面**

**增强的分支预测器**：

```
Intel CET (Control-flow Enforcement Technology):
├─ 影子栈（Shadow Stack）
│  └─ 硬件维护的返回地址栈
├─ 间接分支跟踪
│  └─ 验证间接跳转目标
└─ 预测执行限制
   └─ 限制跨权限边界的预测
```

**ARM的防护**：

```
FEAT_CSV2 (Cache Speculation Variant 2):
├─ 隔离不同安全域的预测
├─ 清除预测状态
└─ 限制预测执行深度
```

---

#### **软件层面**

**编译器缓解**：

```c
// Retpoline技术（return trampoline）
// 将间接跳转转换为return

// 原始代码
jmp *%rax

// Retpoline
call set_up_target
capture_ret_spec:
    pause
    jmp capture_ret_spec
set_up_target:
    mov %rax, (%rsp)
    ret
```

**内核补丁（KPTI）**：

```
页表隔离（Page Table Isolation）
├─ 用户态和内核态使用不同页表
├─ 防止用户程序预测执行读取内核内存
└─ 性能损失：5-30%
```

---

#### **微码更新**

```
Intel/AMD微码更新：
├─ IBRS（Indirect Branch Restricted Speculation）
│  └─ 限制间接分支的预测执行
├─ IBPB（Indirect Branch Predictor Barrier）
│  └─ 清除预测器状态
└─ STIBP（Single Thread Indirect Branch Predictors）
   └─ 隔离同一核心上不同线程的预测器
```

---

### **3. 性能影响**

|缓解措施|性能影响|适用场景|
|---|---|---|
|**Retpoline**|5-20%|内核空间|
|**KPTI**|5-30%|系统调用密集|
|**IBRS**|0-5%|硬件支持|
|**完全禁用预测执行**|50%+|不实用|

**实际部署**：

```
云服务提供商：
├─ 必须部署所有缓解措施
└─ 接受性能损失（安全第一）

嵌入式系统：
├─ 评估威胁模型
└─ 选择性部署
```

## 二十五、前沿研究方向

### **1. 深度学习预测器**

#### **神经网络架构**

```
输入层：
├─ PC的哈希值
├─ 全局分支历史（64-128位）
├─ 局部分支历史

隐藏层：
├─ 2-3层全连接网络
├─ 每层64-256个神经元
└─ ReLU激活函数

└─ Sigmoid输出（预测概率）
```

**训练方法**：

```
在线训练：
├─ 每次分支结果用于更新权重
├─ 梯度下降（感知器算法）
└─ 学习率自适应调整

离线训练：
├─ 收集大量程序的分支trace
├─ 预训练通用模型
└─ 运行时微调
```

**性能**：

```
准确率：98-99%
开销：~10KB权重存储
延迟：2-3周期
```

### **2. 上下文敏感预测**

#### **路径历史**

```
不仅记录分支taken/not taken
还记录到达分支的路径

例如：
Path A → Branch X → taken (90%)
Path B → Branch X → taken (20%)

→ 同一分支，不同路径，不同行为
```

**实现**：

```
路径寄存器（64位）：
├─ 记录最近经过的N个分支的PC哈希
├─ 每个分支将路径寄存器左移并加入新位
└─ 用路径寄存器索引预测表

效果：
准确率提升1-2%
```

---

### **3. 值预测集成**

#### **分支结果 = f(操作数值)**

```
预测分支结果的同时预测操作数值：

if (a > b) ...

不仅预测分支方向
还预测a和b的值
→ 可以更早执行后续指令
```

**挑战**：

```
值预测比分支预测困难得多
├─ 值的范围更大
├─ 值的模式更复杂
└─ 错误代价更高

当前研究：
├─ 只预测高置信度的情况
├─ 结合硬件事务内存
└─ 准确率需>99%才实用
```

### **设计哲学总结**

#### **1. 预测的本质**

```
预测 = 用概率换确定性

如果准确率够高：
预测成本 < 等待成本
→ 预测有利可图
```

#### **2. 复杂度权衡**

```
简单预测器：
优点：快速、低功耗、易实现
缺点：准确率有限

复杂预测器：
优点：准确率高
缺点：面积大、功耗高、延迟长

最优点：在硬件预算内最大化准确率
```

#### **3. 软硬件协同**

```
单靠硬件：有物理极限
单靠软件：性能不足

最佳方案：
硬件提供高效预测机制
软件提供优化和提示
→ 1 + 1 > 2
```
